Authentication

First make one login work. Then add a login screen, session display, logout and inactive-account handling. Provider details and social authentication come later.

Before starting: complete the basic Users tutorial through creating users. You do not need to finish its advanced sections.

1. Install

composer require tihloh/prefab-auth

2. Give Alice a password

Auth needs a password hash. Add the column if you have not already:

ALTER TABLE users ADD password_hash VARCHAR(255) NULL;

Create a hash once from the terminal:

php -r "echo password_hash('secret123', PASSWORD_DEFAULT), PHP_EOL;"

Copy the generated hash and save it for Alice:

UPDATE users
SET password_hash = 'PASTE_HASH_HERE'
WHERE email = 'alice@example.com';
Checkpoint: Alice has an email, password hash and active = 1.

3. Create the smallest Auth user

Create public/login.php. Start with only the contract Auth needs:

<?php
require __DIR__ . '/../vendor/autoload.php';

use Tihloh\Prefab\Auth\Contracts\AuthenticatableUserInterface;

final class LoginUser implements AuthenticatableUserInterface
{
    public function __construct(
        public int $id,
        public string $email,
        private ?string $passwordHash,
        public bool $active,
    ) {}

    public function authId(): int|string { return $this->id; }
    public function authPasswordHash(): ?string { return $this->passwordHash; }
    public function authIsActive(): bool { return $this->active; }
}

Nothing is displayed yet. This slice only defines what Auth considers an authenticatable user.

4. Add a tiny database provider

Under LoginUser, add:

use Tihloh\Prefab\Auth\Contracts\AuthUserProviderInterface;

final class LoginProvider implements AuthUserProviderInterface
{
    public function __construct(private PDO $pdo) {}

    public function findByIdentifier(string $email): ?AuthenticatableUserInterface
    {
        $stmt = $this->pdo->prepare(
            'SELECT id,email,password_hash,active FROM users WHERE email = ? LIMIT 1'
        );
        $stmt->execute([$email]);
        $row = $stmt->fetch(PDO::FETCH_ASSOC);

        return $row ? $this->make($row) : null;
    }

    public function findById(int|string $id): ?AuthenticatableUserInterface
    {
        $stmt = $this->pdo->prepare(
            'SELECT id,email,password_hash,active FROM users WHERE id = ? LIMIT 1'
        );
        $stmt->execute([$id]);
        $row = $stmt->fetch(PDO::FETCH_ASSOC);

        return $row ? $this->make($row) : null;
    }

    private function make(array $row): LoginUser
    {
        return new LoginUser(
            (int) $row['id'],
            $row['email'],
            $row['password_hash'],
            (bool) $row['active'],
        );
    }
}

5. Create AuthManager

Below the classes, connect the database and Auth:

use Tihloh\Prefab\Auth\Services\AuthManager;
use Tihloh\Prefab\Auth\Session\NativeSessionStore;

$pdo = new PDO(
    'mysql:host=127.0.0.1;dbname=prefab_tutorial;charset=utf8mb4',
    'root',
    '',
    [PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION]
);

$auth = new AuthManager(
    new LoginProvider($pdo),
    new NativeSessionStore(),
);

6. Test one login before building a form

Temporarily add this at the bottom:

$result = $auth->attempt('alice@example.com', 'secret123');

echo $result->success ? 'Login works' : 'Login failed';

Run:

php -S 127.0.0.1:8000 -t public

Open http://127.0.0.1:8000/login.php.

Checkpoint: the browser says Login works. Change the password in the code and confirm it says Login failed.

7. Replace the hard-coded login with a form

Remove the temporary $auth->attempt(...) test. Replace it with:

$message = '';

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    $result = $auth->attempt(
        $_POST['email'] ?? '',
        $_POST['password'] ?? '',
    );

    $message = $result->success
        ? 'Login successful.'
        : 'Invalid login.';
}

Then add this after the closing ?>:

<h1>Login</h1>
<p><?= htmlspecialchars($message) ?></p>

<form method="post">
    <p><input name="email" type="email" placeholder="Email" required></p>
    <p><input name="password" type="password" placeholder="Password" required></p>
    <button>Login</button>
</form>
Checkpoint: try a wrong password, then log in with alice@example.com / secret123.

8. Show the current session

Now that login works, add this above the form:

<?php if ($auth->check()): ?>
    <p>Logged in as user #<?= htmlspecialchars((string) $auth->id()) ?></p>
<?php endif; ?>

Refresh after logging in. The session should still exist.

The three most useful read methods are:

$auth->check();
$auth->id();
$auth->user();
Checkpoint: refresh the page and confirm you remain logged in.

9. Add logout

Add this before the login POST handler:

if (isset($_POST['logout'])) {
    $auth->logout();
    $message = 'Logged out.';
}

Inside the logged-in section, add:

<form method="post">
    <button name="logout" value="1">Logout</button>
</form>
Checkpoint: log in, refresh, then log out.

10. Build on it — inactive accounts

Deactivate Alice using the Users tutorial or SQL:

UPDATE users SET active = 0
WHERE email = 'alice@example.com';

Log out and try to sign in again. Then restore her:

UPDATE users SET active = 1
WHERE email = 'alice@example.com';

11. Build on it — request context

Once the basic login is clear, attach useful request information:

$result = $auth->attempt(
    $_POST['email'] ?? '',
    $_POST['password'] ?? '',
    [
        'ip_address' => $_SERVER['REMOTE_ADDR'] ?? null,
        'user_agent' => $_SERVER['HTTP_USER_AGENT'] ?? null,
    ],
);

12. Build on it — authentication result and logs

$result = $auth->attempt($email, $password);

if ($result->success) {
    $logs?->record($result->log);
}

13. Advanced — provider boundary

Why did we create LoginProvider? Auth intentionally does not own your users table. It asks a provider for an object implementing AuthenticatableUserInterface. That lets Auth work with Prefab Users, an existing application, LDAP-style adapters, or another user source.

Important: learn this architecture after the login screen works. You do not need to understand the provider abstraction before testing your first login.

14. Advanced — social authentication

Social login needs OAuth provider credentials, a callback URL and a social-user resolver. Treat it as a separate advanced exercise rather than part of your first login.

$url = $social->authorizationUrl('google');
header('Location: ' . $url);

After the provider redirects back:

$result = $social->callback('google', $_GET);

Account management:

$accounts = $social->accountsForUser($userId);
$social->unlink($userId, 'google');
Finished: you progressed from one hard-coded authentication attempt to a real login form, persistent session, logout, inactive-user handling and finally the advanced extension points.
