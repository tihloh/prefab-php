Authentication

Start with the shortest useful Auth setup: one PDO connection, Prefab Users, a password and a login form. PIN, tokens, social login and custom identifier rules are optional features introduced later.

1. Install

composer require tihloh/prefab-auth

2. Create Users and Auth

Create public/login.php and reuse the same PDO connection from the Users tutorial.

<?php
require __DIR__ . '/../vendor/autoload.php';

use Tihloh\Prefab\Users\Services\UserManager;
use Tihloh\Prefab\Auth\Services\AuthManager;

$pdo = new PDO(
    'mysql:host=127.0.0.1;dbname=prefab_tutorial;charset=utf8mb4',
    'root',
    '',
    [PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION]
);

$users = new UserManager([
    'database' => $pdo,
]);

$auth = new AuthManager([
    'database' => $pdo,
]);

Users owns identity/profile data. Auth owns credentials and sessions. Because Users is registered first, Auth can reuse its user provider automatically.

3. Give a user a password

Load Alice from the previous tutorial and set a password once:

$alice = $users->findByEmail('alice@example.com');

if ($alice && !$auth->hasPassword($alice->id)) {
    $auth->setPassword($alice->id, 'secret123');
}

Prefab stores a password hash, not the plain password.

Checkpoint: The page loads without creating password columns in the users table.

4. Login

Add the handler:

$message = '';

if (isset($_POST['login'])) {
    $result = $auth->attempt(
        $_POST['identifier'] ?? '',
        $_POST['password'] ?? '',
    );

    $message = $result->success
        ? 'Login successful.'
        : 'Invalid login.';
}

Add the form:

?>
<h1>Login</h1>
<p><?= htmlspecialchars($message) ?></p>

<form method="post">
    <input name="identifier" placeholder="Email" required>
    <input name="password" type="password" placeholder="Password" required>
    <button name="login" value="1">Login</button>
</form>

For this first example, enter alice@example.com and secret123. The first argument is called an identifier because advanced projects may later use usernames or other login names.

Checkpoint: The form should display Login successful.

5. Current user and logout

if ($auth->check()) {
    echo 'User #' . htmlspecialchars((string) $auth->id());
}

// $auth->user();   // current user object
// $auth->logout(); // end the session

All supported login methods create the same Auth session, so the rest of the application can use check(), id(), user() and logout() without caring how the user authenticated.

6. Optional: email-only or username login

The default identifier mode is flexible. A project that wants email only can be explicit:

$auth = new AuthManager([
    'database' => $pdo,
    'identifier_mode' => 'email',
]);

For an existing table with a username column, map it through Users:

use Tihloh\Prefab\Users\Mapping\UserMap;

$map = new UserMap(
    table: 'employees',
    id: 'employee_id',
    name: 'full_name',
    email: 'email_address',
    active: 'is_active',
    attributes: [
        'username' => 'username',
    ],
);

$users = new UserManager([
    'database' => $pdo,
    'map' => $map,
]);

No manual provider construction is needed.

7. Optional: PIN

$auth->setPin($alice->id, '1234');
$result = $auth->attemptPin('alice@example.com', '1234');

PINs are hashed separately from passwords. They are useful only when the application intentionally wants a shorter credential and has appropriate rate limiting.

8. Optional: one-time login token

$token = $auth->createLoginToken($alice->id);
$result = $auth->attemptToken($token);

Normal login tokens are short-lived and single-use, which makes them suitable for magic links or temporary access.

9. Optional: remember login

For persistent browser login, issue a remember token instead of storing the password:

$token = $auth->createRememberToken($alice->id);

Store the token in a Secure, HttpOnly cookie. When the normal session is missing:

$auth->attemptToken($token, 'remember');

To invalidate remembered sessions:

$auth->revokeLoginTokens($alice->id, 'remember');

10. Optional: password-only-next-login behavior

Do not save the user's plain password. Use the built-in one-time next-login token:

$token = $auth->createNextLoginToken($alice->id);
$auth->attemptToken($token, 'next_login');

11. Optional: URL token login

URL login is disabled by default. Prefer one-time tokens over reusable passwords in URLs.

$auth = new AuthManager([
    'database' => $pdo,
    'url_login' => [
        'allow_token' => true,
        'allow_password' => false,
    ],
]);

$result = $auth->attemptFromQuery($_GET);

Then a link may contain ?token=... or its configured alias. Raw password URLs should remain disabled unless a controlled legacy integration specifically requires them.

12. Optional: password management

$auth->hasPassword($alice->id);
$auth->verifyPassword($alice->id, 'secret123');
$auth->changePassword($alice->id, 'secret123', 'new-secret-456');
$auth->removePassword($alice->id);

13. Optional: social login

SocialAuthManager can connect providers such as Google or GitHub. A successful social login creates the same normal Auth session as password, PIN and token login.

$url = $social->authorizationUrl('google');
$result = $social->callback('google', $_GET);

14. Optional: custom identifier rules

Employee numbers, phone numbers or other formats can use a custom validator:

$auth = new AuthManager([
    'database' => $pdo,
    'identifier_validator' => fn (string $value): bool =>
        preg_match('/^EMP-\d{5}$/', $value) === 1,
]);

15. Optional: custom storage

Most applications should keep the simple manager configuration. Lower-level integrations can replace the built-in stores through:

AuthCredentialStoreInterface
PinCredentialStoreInterface
LoginTokenStoreInterface

16. Diagnostics and audit context

print_r($auth->explain());

Authentication attempts can also include request context for Prefab Logs:

$result = $auth->attempt(
    $_POST['identifier'] ?? '',
    $_POST['password'] ?? '',
    [
        'ip_address' => $_SERVER['REMOTE_ADDR'] ?? null,
        'user_agent' => $_SERVER['HTTP_USER_AGENT'] ?? null,
    ],
);

Works with other Prefab modules

Prefab Auth can discover the project user provider, reuse shared storage, publish the current actor and send authentication activity to Logs.

ModuleIntegrationHowWhat happens
UsersAutomaticuser_provider capabilityAuth reuses the same user identity/profile records.
DatabaseAutomatic when storage is neededdatabase capabilityAuth can reuse shared storage for credentials, PINs and login tokens.
LogsAutomaticlogger capabilityAuthentication activity can be recorded without manually logging every Auth operation.
Users / Permissions / other modulesAutomatic shared actoractor_provider capabilityCompatible modules can use the authenticated user ID as the audit actor.
PermissionsDirect compositionauth.id() → permissions.can()Auth answers who is logged in; Permissions answers what that user may do.
RoutesCompatible hookroute.auth() + middlewareRoute middleware can query Auth before running a protected handler.
Keep it simple: Start with password login. Add PIN, tokens, social providers or custom stores only when the project actually needs them.
