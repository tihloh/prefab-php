Authentication

This tutorial adds password authentication and sessions to the users created in the Users tutorial. Password credentials are stored by Auth, so the user profile table remains unchanged.

1. Install

composer require tihloh/prefab-auth

2. Load Alice from Prefab Users

Create public/login.php and connect to the existing Users setup:

<?php
require __DIR__ . '/../vendor/autoload.php';

use Tihloh\Prefab\Users\Mapping\UserMap;
use Tihloh\Prefab\Users\Repositories\PdoUserProvider;
use Tihloh\Prefab\Users\Services\UserManager;

$pdo = new PDO(
    'mysql:host=127.0.0.1;dbname=prefab_tutorial;charset=utf8mb4',
    'root',
    '',
    [PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION]
);

$users = new UserManager(
    new PdoUserProvider($pdo, new UserMap(table: 'users'))
);

$alice = $users->findByEmail('alice@example.com');
Checkpoint: $alice should contain the Alice user created in the Users tutorial.

3. Create AuthManager

Add the Auth manager:

use Tihloh\Prefab\Auth\Services\AuthManager;

$auth = new AuthManager([
    'database' => $pdo,
]);

Auth uses the available user identity source and stores password credentials separately. The first password operation creates the prefab_auth_credentials table automatically.

4. Set the first password

Set a password for Alice:

$auth->setPassword($alice->id, 'secret123');
echo 'Password created';

Open http://127.0.0.1:8000/login.php.

Checkpoint: The page should display Password created. The database should also contain prefab_auth_credentials.

5. Test authentication

Remove the temporary setPassword() lines and replace them with:

$result = $auth->attempt(
    'alice@example.com',
    'secret123'
);

echo $result->success
    ? 'Login works'
    : 'Login failed';
Checkpoint: The correct password should display Login works. An incorrect password should display Login failed.

6. Create a login form

Replace the hard-coded authentication test with:

$message = '';

if (isset($_POST['login'])) {
    $result = $auth->attempt(
        $_POST['email'] ?? '',
        $_POST['password'] ?? '',
    );

    $message = $result->success
        ? 'Login successful.'
        : 'Invalid login.';
}
?>

Add the form:

<h1>Login</h1>
<p><?= htmlspecialchars($message) ?></p>

<form method="post">
    <p><input name="email" type="email" placeholder="Email" required></p>
    <p><input name="password" type="password" placeholder="Password" required></p>
    <button name="login" value="1">Login</button>
</form>
Checkpoint: Sign in with alice@example.com and secret123.

7. Read the current session

Add this above the login form:

<?php if ($auth->check()): ?>
    <p>Logged in as user #<?= htmlspecialchars((string) $auth->id()) ?></p>
<?php endif; ?>

The current authentication state is available through:

$auth->check();
$auth->id();
$auth->user();
Checkpoint: Refresh the page after logging in. The authenticated session should remain active.

8. Add logout

Add a logout handler before the login handler:

if (isset($_POST['logout'])) {
    $auth->logout();
    $message = 'Logged out.';
}

Add a logout button inside the logged-in section:

<form method="post">
    <button name="logout" value="1">Logout</button>
</form>
Checkpoint: Log in, refresh the page, and then log out.

9. Check whether a password exists

if ($auth->hasPassword($alice->id)) {
    echo 'Alice has a password';
}

10. Verify a password without logging in

$ok = $auth->verifyPassword(
    $alice->id,
    'secret123'
);

11. Change a password

$changed = $auth->changePassword(
    $alice->id,
    'secret123',
    'new-secret-456'
);

When $changed is true, the old password no longer authenticates the user.

12. Reset or remove a password

An administrative or password-reset flow can assign a new password directly:

$auth->setPassword(
    $alice->id,
    'reset-password-789'
);

A password can also be removed:

$auth->removePassword($alice->id);

13. Inactive accounts

Authentication respects the user's active status:

$users->update($alice->id, [
    'active' => false,
]);

After Alice is inactive, sign-in attempts should fail. Restore the account afterward:

$users->update($alice->id, [
    'active' => true,
]);

14. Advanced: request context and logs

Authentication attempts can include request information for logging and auditing:

$result = $auth->attempt(
    $_POST['email'] ?? '',
    $_POST['password'] ?? '',
    [
        'ip_address' => $_SERVER['REMOTE_ADDR'] ?? null,
        'user_agent' => $_SERVER['HTTP_USER_AGENT'] ?? null,
    ],
);

15. Advanced: custom credential stores

The built-in PDO credential store is the default. Applications can provide another implementation of AuthCredentialStoreInterface when credentials need to be stored elsewhere.

16. Advanced: legacy providers

Providers that already expose a password hash through authPasswordHash() remain supported as a compatibility fallback. New applications can keep password credentials entirely within Auth.

17. Advanced: social authentication

Social authentication uses an OAuth provider and does not require password credentials.

$url = $social->authorizationUrl('google');
header('Location: ' . $url);

Handle the provider callback with:

$result = $social->callback('google', $_GET);
