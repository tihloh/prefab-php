Messaging

Messaging sends a message through a named delivery channel. A channel might be email, SMS, a webhook or a project-specific transport. This tutorial begins with a local test channel so the complete delivery flow can be understood before SMTP credentials are introduced.

1. Install Messaging

composer require tihloh/prefab-messaging

MessagingManager coordinates delivery. Message contains the content. Recipient contains destination information. A channel knows how to deliver that message to that recipient.

2. Create a local test channel

Create public/messaging.php:

<?php
require __DIR__ . '/../vendor/autoload.php';

use Tihloh\Prefab\Messaging\Channels\CallableChannel;
use Tihloh\Prefab\Messaging\MessagingManager;
use Tihloh\Prefab\Messaging\Message;
use Tihloh\Prefab\Messaging\Recipient;

$messages = [];

$testChannel = new CallableChannel(
    'test',
    function (Recipient $recipient, Message $message) use (&$messages) {
        $messages[] = [
            'recipient' => $recipient,
            'subject' => $message->subject,
            'text' => $message->text,
        ];

        return 'TEST-' . time();
    }
);

$messaging = new MessagingManager([$testChannel]);

CallableChannel is useful for learning and tests because it does not contact an external service. Instead, its callback receives exactly what a real channel would receive.

The channel name is test. Later, send('test', ...) selects this channel. The callback captures the message in $messages and returns a fake external delivery ID.

3. Send one message

Add a temporary send call:

$recipient = new Recipient([
    'test' => 'demo@example.com',
]);

$result = $messaging->send(
    'test',
    $recipient,
    new Message(
        'Prefab test',
        'Hello from Prefab Messaging',
    ),
);

print_r($result);

The recipient can hold destinations for different channels. Here the test channel receives demo@example.com. A real recipient could contain a mail address, phone number or another channel-specific identifier.

send() selects the channel, resolves the recipient destination, passes the message to the channel, and returns a delivery result describing success or failure.

Checkpoint: The page should show a successful delivery result from the local test channel without sending anything externally.

4. Build a browser form

Remove the temporary send call and add:

$result = null;

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    $recipient = new Recipient([
        'test' => $_POST['to'] ?? 'demo@example.com',
    ]);

    $result = $messaging->send(
        'test',
        $recipient,
        new Message(
            $_POST['subject'] ?? 'Prefab test',
            $_POST['body'] ?? 'Hello from Prefab Messaging',
        ),
    );
}

Add the form:

<h1>Prefab Messaging Test</h1>
<form method="post">
    <p><input name="to" value="demo@example.com"></p>
    <p><input name="subject" value="Prefab test"></p>
    <p><textarea name="body">Hello from Prefab Messaging</textarea></p>
    <button>Send test message</button>
</form>

Display both the delivery result and the captured message:

<?php if ($result): ?>
    <h2>Delivery result</h2>
    <pre><?= htmlspecialchars(print_r($result, true)) ?></pre>

    <h2>Captured message</h2>
    <pre><?= htmlspecialchars(print_r($messages, true)) ?></pre>
<?php endif; ?>

This page verifies the entire application-side flow while keeping external infrastructure out of the equation.

5. Understand delivery hooks

$messaging->on('sending', function () {
    // Runs before delivery.
});

$messaging->on('sent', function () {
    // Runs after successful delivery.
});

$messaging->on('failed', function () {
    // Runs after failed delivery.
});

Hooks let other parts of the application react without changing the channel itself. For example, a sent hook could write an audit log, while a failed hook could record an error or queue a retry.

The order is conceptually:

Application calls send()
        ↓
sending hook
        ↓
channel delivers message
        ↓
sent hook OR failed hook
        ↓
DeliveryResult returned

6. Use the mail convenience API

$result = $messaging->mail(
    'user@example.com',
    'Annual Report',
    'Your report is ready.',
);

mail() is a shortcut for the common email case. It requires a channel registered under the name mail. If no mail channel exists, the manager has nowhere to deliver the message.

7. Configure real SMTP

Once the local channel works, add a real mail transport:

use Tihloh\Prefab\Messaging\Channels\MailChannel;
use Tihloh\Prefab\Messaging\Mail\SmtpTransport;

$smtp = new SmtpTransport([
    'host' => 'smtp.example.com',
    'port' => 587,
    'username' => 'user@example.com',
    'password' => 'secret',
    'encryption' => 'tls',
    'from' => [
        'address' => 'noreply@example.com',
        'name' => 'My System',
    ],
]);

$messaging = new MessagingManager([
    new MailChannel($smtp),
]);

SmtpTransport contains the connection details required to talk to the mail server. MailChannel adapts that transport to the common Messaging channel interface.

Send a real message:

$result = $messaging->mail(
    'recipient@example.com',
    'SMTP Test',
    'This message was sent through SMTP.',
);

If the local test succeeds but SMTP fails, the problem is likely transport configuration rather than application message construction. That is why the local channel comes first.

8. Generic channels

$result = $messaging->send(
    'sms',
    $recipient,
    new Message('OTP', 'Your code is 123456'),
);

The manager does not need to know how SMS works. It only needs a registered sms channel. This is the central design idea of Messaging: application code depends on the messaging abstraction, while channels contain transport-specific behavior.

9. Templates

$template = new Template(
    subject: 'Hello {{name}}',
    text: 'Your report {{report}} is ready.'
);

$message = $template->render([
    'name' => 'Demo User',
    'report' => 'AR-2026',
]);

Templates separate reusable wording from individual recipient data. Rendering replaces placeholders with actual values and produces a normal Message for delivery.

10. Attachments

$message = new Message(
    subject: 'Report',
    text: 'Your report is attached.',
    attachments: [
        Attachment::fromPath('/tmp/report.pdf'),
    ],
);

Attachment::fromPath() points to an existing file. Attachment::fromData() can be used when the content already exists in memory instead of on disk.

11. Advanced hook arguments

$messaging->on('sending', function ($channel, $recipient, $message) {});
$messaging->on('sent', function ($channel, $recipient, $message, $result) {});
$messaging->on('failed', function ($channel, $recipient, $message, $result) {});

The richer callback signatures expose the channel, recipient, message and result so integration code can make decisions based on what was actually delivered.

Finished: The tutorial sequence now ends with a message that can be tested locally first and then delivered through a real transport without changing the application-facing messaging API.

Works with other Prefab modules

Prefab Messaging is the outbound-delivery layer. It can be combined with any module that produces an event, but it does not silently send messages when those modules change data.

ModuleIntegrationHowWhat happens
NotificationsDirect compositionsend both when neededCreate an in-app notification and send an external email/message from the same application action when both channels are appropriate.
UsersDirect compositionuser email → Recipient::email()A user profile email can become a mail recipient without Messaging depending directly on Prefab Users.
AuthDirect compositionsecurity messagesPassword-reset, login-token or security flows can send links/tokens through registered Messaging channels.
LogsHook-based compositionon(sending/sent/failed)Messaging lifecycle hooks can be recorded in Prefab Logs when delivery auditing is required.
Custom providersBuilt-in extensionChannelInterfaceEmail, SMS, chat, push or another delivery service can be added as a channel while the application keeps using MessagingManager::send().
Important: Messaging does not auto-send on Users/Auth/Notifications events. External communication is a side effect that applications should opt into deliberately.
