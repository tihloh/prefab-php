Audit Logs

Turn audit records into a simple activity screen. Start by recording one event, then show recent activity in a UI a user or administrator can actually read.

1. Install Logs

composer require tihloh/prefab-logs

2. Start Logs

If a Prefab database capability is already available, keep setup short:

use Tihloh\Prefab\Logs\Services\LogManager;

$logs = new LogManager();

Logs can reuse the shared Prefab database automatically. The module owns its technical log storage.

3. Record an event

$logs->record([
    'action' => 'document.approved',
    'subject_type' => 'document',
    'subject_id' => 1001,
    'actor_id' => 1,
    'message' => 'Document was approved.',
]);

action is the machine-readable event name. The subject identifies what changed, the actor identifies who caused it, and message is what people can read.

4. Load recent activity

$recent = $logs->recent(20);

This gives you the newest records for an activity screen or dashboard.

5. Show an activity list

Do not dump the log array. Give the student a small UI that already looks useful:

<h2>Recent activity</h2>

<?php foreach ($recent as $log): ?>
    <div class="card card-body mb-2">
        <strong><?= htmlspecialchars($log['message'] ?? $log['action']) ?></strong>
        <small class="text-muted">Actor #<?= $log['actor_id'] ?? 'System' ?></small>
    </div>
<?php endforeach; ?>
Checkpoint: The browser should now show “Document was approved.” as an activity item.

6. Query useful history

$logs->recent(50);
$logs->forSubject('document', 1001);
$logs->forActor(1);

forSubject() answers “what happened to this record?” while forActor() answers “what did this user do?”

7. Show human-friendly activity

When IDs need readable labels, let Logs prepare human-facing records:

$activity = $logs->humanRecent(
    20,
    actorResolver: fn ($id) => "User #{$id}",
    subjectResolver: fn ($type, $id) => "{$type} #{$id}",
);

You can render $activity with the same small card/list pattern instead of exposing the raw database record.

8. Store structured changes

$logs->record([
    'action' => 'user.updated',
    'subject_type' => 'user',
    'subject_id' => 25,
    'actor_id' => 7,
    'changes' => [
        'office' => ['old' => 'Accounting', 'new' => 'Budget'],
    ],
]);

Structured changes make it possible to later show exactly what changed without parsing a message string.

9. Automatic logging

When compatible modules such as Users are installed, normal operations can create logs automatically:

$logs = new LogManager();
$users = new UserManager(['database' => $pdo]);

$users->create([
    'name' => 'Alice',
    'email' => 'alice@example.com',
]);

The application does not need a second $logs->record() for the user creation when the logger capability is available.

10. Developer tip: diagnostics

print_r($logs->explain());

Use diagnostics only when storage or automatic integration is not resolving as expected. The normal tutorial result is the activity screen.

Automatic logging and module coexistence

Prefab Logs publishes a logger capability that compatible modules can discover, so normal module operations can produce audit records without repeating LogManager::record() throughout application code.

ModuleIntegrationHowWhat happens
UsersAutomatic logginguser.created / user.updated / user.deletedUserManager produces structured changes and sends them to the discovered logger. Actor information can come automatically from Auth.
AuthAutomatic loggingauth.* eventsAuthentication activity can be sent to Logs automatically when Auth discovers the logger capability.
PermissionsAutomatic loggingpermission.granted / denied / clearedPermission changes emit structured log payloads that the Prefab runtime can forward to Logs.
DatabaseAutomatic storage reusedatabase capabilityLogs can build its PDO repository from the shared database without a separate database setup.
Other modules / app codeCompatiblelogger capability / record()Application code can call record() directly for domain-specific events.
Important: Automatic logging does not mean Logs watches the database. Compatible modules emit structured events while performing their operations.
