Audit Logs

Record structured application activity, then present the event, its details, and creation time separately.

1. Install

composer require tihloh/prefab-logs

2. Start Logs

use Tihloh\Prefab\Logs\Services\LogManager;
$logs = new LogManager();

3. Record a simple event

$logs->record([
'action' => 'document.approved',
'subject_type' => 'document',
'subject_id' => 1001,
'actor_id' => 1,
]);
Checkpoint: One structured event is now stored. Do not build the display sentence into the timestamp.

4. Record what changed

$logs->record([
'action' => 'user.updated',
'subject_type' => 'user',
'subject_id' => 25,
'actor_id' => 7,
'changes' => [
'office' => ['old' => 'Accounting', 'new' => 'Budget'],
'active' => ['old' => false, 'new' => true],
],
]);

Structured changes let the human view explain what happened instead of only saying that a record was updated.

5. Human-friendly recent activity

$recent = $logs->humanRecent(
20,
actorResolver: fn ($id) => $users->find($id)?->name,
subjectResolver: fn ($type, $id) => $type === 'user'
? $users->find($id)?->name
: null,
);

Each presented row keeps the three display concerns separate:

$log['event'];      // Demo Admin updated Test User.
$log['details'];    // before/after change rows
$log['created_at']; // when the log record was created

summary remains a compatibility alias for event, but new UIs should use event.

6. Build a readable activity table

<table border="1" cellpadding="8">
<tr>
<th>Event</th>
<th>Details</th>
<th>Created</th>
</tr>
<?php foreach ($recent as $log): ?>
<tr>
<td><?= htmlspecialchars($log['event']) ?></td>
<td>
<?php foreach ($log['details'] as $change): ?>
<div>
<?= htmlspecialchars($change['field']) ?>:
<?= htmlspecialchars($change['old']) ?> →
<?= htmlspecialchars($change['new']) ?>
</div>
<?php endforeach; ?>
</td>
<td><?= htmlspecialchars((string) $log['created_at']) ?></td>
</tr>
<?php endforeach; ?>
</table>
Checkpoint: Event text, change details, and creation time now have independent columns.

7. Query useful history

$logs->recent(50);
$logs->forSubject('document', 1001);
$logs->forActor(1);

8. Technical vs human view

Use recent() when you need the original technical audit fields. Use humanRecent() for an activity feed. Both come from the same stored structured record.

9. Developer trace

$logs->record($data);
prefab_trace();

For detailed diagnostics:

prefab_trace_detailed();

Trace output is temporary developer diagnostics. Prefab Logs is persistent application/audit history.

10. Configuration diagnostics

print_r($logs->explain());

Automatic logging and module coexistence

UsersUser writes can produce structured audit records.
AuthAuthentication activity can be recorded.
PermissionsPermission changes can be recorded.
Core DatabaseLogs can reuse shared persistence infrastructure.
