Audit Logs

Add reusable technical audit history without scattering manual INSERT statements around your application.

Install

composer require tihloh/prefab-logs

Better together

Users ── user_provider ──┐
                         ├──→ Auth
Logs  ── logger ─────────┘

Permissions ── authorization events ──→ Logs

When Logs is available, compatible modules can publish infrastructure events such as login, logout, failed login, user changes and permission changes.

Logs should not invent business events. Installing it may enhance compatible infrastructure behavior, but your application still chooses business actions such as “document approved” or “invoice paid”.

Typical direct use

$logs->record([
    'action' => 'document.approved',
    'subject_type' => 'document',
    'subject_id' => $documentId,
    'message' => 'Document was approved.',
]);
Checkpoint: perform a login or user change and confirm the event reaches the configured log store.
