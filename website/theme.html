Tutorial · Theme

Shared appearance policy without theme-specific application markup.

Prefab Theme adds theme, light/dark/system mode, density, user preference policy and optional reusable admin structures to normal Bootstrap applications.

Keep normal Bootstrap markup. Themes change semantic Prefab tokens and Bootstrap presentation. Application pages should not be rewritten with theme-specific classes.

1. Install Theme

composer require tihloh/prefab-theme

Prefab Core is installed transitively. Bootstrap remains an application dependency.

2. Configure application policy

use Tihloh\Prefab\Theme\ThemeManager;

$themes = new ThemeManager([
    'default' => 'default',
    'mode' => 'system',
    'density' => 'comfortable',
    'themes' => [
        'default' => ['modes' => ['light', 'dark']],
    ],
    'user' => [
        'enabled' => true,
        'theme' => false,
        'mode' => true,
        'density' => true,
    ],
]);

The application decides which themes are enabled and which appearance settings a user is allowed to change.

3. Apply user appearance once

$themes->apply($userAppearance ?? []);

A missing user value inherits the application default. Direct application policy always wins over user preferences.

4. Render Theme in the layout

<!doctype html>
<html <?= $themes->attributes() ?>>
<head>
    <link rel="stylesheet" href="/assets/bootstrap.min.css">
    <?= $themes->styles() ?>
</head>
<body>
    <!-- normal Bootstrap markup -->

    <script src="/assets/bootstrap.bundle.min.js"></script>
    <?= $themes->scripts() ?>
</body>
</html>

Theme defaults to inline package assets, so normal usage does not require a publish/copy step.

5. Keep application markup theme-independent

<div class="card">
    <div class="card-body">
        <input class="form-control" type="text">
        <button class="btn btn-primary">Save</button>
    </div>
</div>

Avoid classes such as win11-card or dark-input. The active theme should change appearance without changing business-page markup.

6. Add user controls anywhere

<button pf:theme="default">Default</button>

<button pf:theme-mode="light">Light</button>
<button pf:theme-mode="dark">Dark</button>
<button pf:theme-mode="system">System</button>
<button pf:theme-mode="toggle">Toggle</button>

<button pf:theme-density="comfortable">Comfortable</button>
<button pf:theme-density="compact">Compact</button>

These controls respect application policy. The generic pf:mode namespace remains free for broader Prefab use.

7. Persist appearance

$themes = new ThemeManager([
    'save_url' => '/account/appearance',
]);

When save_url is configured, browser changes are POSTed to the application. Otherwise Theme can persist browser preference through localStorage.

8. Optional admin structures

'components' => [
    'admin' => true,
],

The optional admin layer supplies application-level structures that Bootstrap does not define, such as pf-shell, pf-sidebar, pf-topbar, pf-page, pf-panel, pf-status and pf-timeline.

<div class="pf-shell">
    <aside class="pf-sidebar">...</aside>
    <div class="pf-workspace">
        <header class="pf-topbar">...</header>
        <main class="pf-main">...</main>
    </div>
</div>

If the sidebar or topbar is omitted, the remaining layout naturally occupies the free space; no no-sidebar or no-topbar class is required.

9. Optional published assets

Inline assets are the default. Static publishing is available only when the deployment specifically wants files/CDN serving:

$themes = new ThemeManager([
    'asset_mode' => 'published',
    'public_path' => __DIR__ . '/public/assets/prefab-theme',
    'asset_url' => '/assets/prefab-theme',
]);

$themes->publish();

10. Diagnostics

$themes->explain($userAppearance ?? []);

This reports effective appearance, enabled/installed themes, registry errors and user policy.

Checkpoint: Switch between light/dark/system modes without changing application markup. The same Bootstrap page should follow the active Prefab theme automatically.
