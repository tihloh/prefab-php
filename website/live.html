Tutorial · Live

Server-driven reactive UI with normal PHP.

Prefab Live keeps component state and actions on the server. Small pf:* attributes connect ordinary HTML controls to PHP without requiring React, Vue, Alpine, jQuery or a frontend build step.

Prefab Live is not a frontend framework. Your application still owns routing, authorization, persistence and page structure. Live owns the reusable request/state/render plumbing inside a mounted component.

1. Install Live

composer require tihloh/prefab-live

2. Create a component

<?php

use Tihloh\Prefab\Live\Attributes\Action;
use Tihloh\Prefab\Live\Component;

final class Counter extends Component
{
    public int $count = 0;

    protected function mount(int $start = 0): void
    {
        $this->count = $start;
    }

    #[Action]
    public function increment(): void
    {
        $this->count++;
    }

    public function render(): string
    {
        return <<<HTML
        <button pf:click="increment">Count: {$this->count}</button>
        <span pf:loading>Updating...</span>
        HTML;
    }
}

Public properties are component state. Browser requests may call only public methods explicitly marked with #[Action].

3. Register the component

use Tihloh\Prefab\Live\ComponentRegistry;
use Tihloh\Prefab\Live\LiveManager;

$registry = new ComponentRegistry();
$registry->register('counter', Counter::class);

$live = new LiveManager(
    registry: $registry,
    signingKey: $_ENV['PREFAB_LIVE_KEY'],
    endpoint: '/prefab/live',
);

Use a private signing key of at least 32 bytes. The browser sends a component alias such as counter; it never chooses arbitrary PHP class names.

4. Mount it in a page

<?= $live->mount('counter', ['start' => 5]) ?>

<script src="/assets/prefab-live.js" defer></script>

The current runtime is a small vanilla-JavaScript bridge. No JavaScript application code is required for ordinary Live actions.

5. Handle the Live endpoint

$payload = LiveManager::decodeRequest(
    file_get_contents('php://input') ?: ''
);

$response = $live->handle(
    $payload,
    $_SERVER['HTTP_X_CSRF_TOKEN'] ?? null,
);

header('Content-Type: application/json');
echo json_encode($response, JSON_THROW_ON_ERROR);

The host application owns the HTTP route and response handling. Live restores signed state, applies permitted updates, calls the requested action and renders the next component HTML.

6. Bind normal and reactive form values

Plain pf:model collects a value when another Live action is sent:

<input pf:model="name">

Reactive fields can send themselves:

<input pf:model.live="search">
<input pf:model.live.debounce.400ms="email">
<input pf:model.blur="recordNo">

Use .live for immediate updates, .debounce.400ms for delayed updates such as database availability checks, and .blur when validation should wait until the user leaves the field. Nested paths such as pf:model="filters.search" remain supported.

7. Normalize and validate with Prefab Input

When prefab-input is installed, a Live component can reuse the same normalization and validation rules:

protected function rules(): array
{
    return [
        'email' => 'trim|lowercase|required|email',
        'username' => 'trim|lowercase|required|string|max:30',
        'recordNo' => 'trim|uppercase|required|string',
    ];
}

A reactive request applies the processed value back to component state, so an email such as USER@Example.COM can become user@example.com on the server without duplicating formatting logic in JavaScript.

8. Check uniqueness or existence through the application

Prefab Live deliberately does not know database tables. The component supplies application checks:

protected function liveChecks(): array
{
    return [
        'email' => fn (mixed $value): ?string =>
            $this->users->emailExists((string) $value)
                ? 'Email is already registered.'
                : null,

        'username' => fn (mixed $value): ?string =>
            $this->users->usernameExists((string) $value)
                ? 'Username is already taken.'
                : null,

        'recordNo' => fn (mixed $value): ?string =>
            $this->documents->recordExists((string) $value)
                ? 'Record number already exists.'
                : null,
    ];
}

The same pattern works for employee IDs, student numbers, OBR numbers, invoice numbers, SKUs, voucher codes or any other application-defined value.

<input pf:model.live.debounce.400ms="email">
<small pf:loading="email">Checking...</small>
<small pf:error="email"></small>

pf:error displays the current field error and Live adds aria-invalid automatically. Field-scoped pf:loading appears only while that field is being checked.

9. Validate again before saving

#[Action]
public function save(): void
{
    if (!$this->validate()) {
        return;
    }

    // Persist the current values.
}

Live availability feedback is not a database guarantee. Final actions must rerun validation, and real uniqueness should still be protected by database unique constraints because concurrent requests can pass the same availability check.

10. Protect server-controlled state

use Tihloh\Prefab\Live\Attributes\Locked;

#[Locked]
public int $documentId;

A signed snapshot prevents modification of previous state, while #[Locked] additionally prevents a browser model update from changing that public property. Authorization still belongs inside your application/action.

11. Understand the request cycle

browser action
    ↓
verify signed snapshot
    ↓
resolve registered component
    ↓
restore public state
    ↓
apply pf:model updates
    ↓
optional Input rules + liveChecks
    ↓
call #[Action]
    ↓
render HTML
    ↓
sign next snapshot
    ↓
update only the component

12. Lifecycle

protected function mount(): void {}
protected function hydrate(): void {}
protected function dehydrate(): void {}

mount() runs on initial mounting, hydrate() after signed state is restored for a Live request, and dehydrate() at the end of the render cycle.

13. Responsibility boundary

Prefab Live owns:
component state + signed protocol + browser bridge + component rendering

Your application owns:
database + authorization + page routing + business rules + overall architecture
Checkpoint: If clicking the counter changes only the mounted component without a full page reload or application-written AJAX code, Prefab Live is working.
