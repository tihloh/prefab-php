Permissions

Authentication answers “who is the user?” Permissions answers “what is that user allowed to do?” Build a small permission-management screen with plain HTML.

1. Install Permissions

composer require tihloh/prefab-permissions

2. Define permissions

Create config/permissions.php:

<?php
return [
    'documents.view' => [
        'name' => 'View Documents',
        'default' => true,
    ],
    'documents.approve' => [
        'name' => 'Approve Documents',
        'default' => false,
    ],
];

A new user can view documents by default but cannot approve them until permission is granted.

3. Create a subject

use Tihloh\Prefab\Permissions\Contracts\PermissionSubjectInterface;

final class TutorialSubject implements PermissionSubjectInterface
{
    public function __construct(public int $id, public array $groups = []) {}
    public function permissionSubjectId(): int|string { return $this->id; }
    public function permissionGroupIds(): array { return $this->groups; }
}

4. Connect Permissions

$permissions = new PermissionManager(
    __DIR__ . '/../config/permissions.php',
    new PdoPermissionStore($pdo),
);

$user = new TutorialSubject(1, [10]);

5. Change a permission

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    $permission = $_POST['permission'];
    $action = $_POST['action'];

    if ($action === 'allow') $permissions->set('user', 1, $permission, true);
    if ($action === 'deny')  $permissions->set('user', 1, $permission, false);
    if ($action === 'clear') $permissions->clear('user', 1, $permission);
}

$results = $permissions->resolvedFor($user);

6. Add permission controls

<form method="post">
    <select name="permission">
        <option>documents.view</option>
        <option>documents.approve</option>
    </select>
    <button name="action" value="allow">Allow</button>
    <button name="action" value="deny">Deny</button>
    <button name="action" value="clear">Inherit</button>
</form>

7. Display effective permissions

A table makes the permission state much easier to understand than debug output:

<table border="1" cellpadding="8">
    <tr><th>Permission</th><th>Result</th><th>Source</th></tr>
    <?php foreach ($results as $id => $result): ?>
    <tr>
        <td><?= htmlspecialchars($id) ?></td>
        <td><?= $result->allowed ? 'ALLOW' : 'DENY' ?></td>
        <td><?= htmlspecialchars($result->source) ?></td>
    </tr>
    <?php endforeach; ?>
</table>
Checkpoint: Change documents.approve between Allow, Deny and Inherit and watch the table update.

8. Resolution order

User override
    ↓ if absent
Group overrides
    ↓ if absent
Definition default

9. Everyday API

$permissions->can($user, 'documents.approve');
$permissions->resolve($user, 'documents.approve');
$permissions->set('user', 1, 'documents.approve', true);
$permissions->clear('user', 1, 'documents.approve');

10. Developer tip

print_r($permissions->explain());

Use diagnostics only when debugging configuration or integration.
