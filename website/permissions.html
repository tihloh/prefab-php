Permissions

Authentication answers who the user is. Permissions answers what that user may do.

Install

composer require tihloh/prefab-permissions

Permission definitions

The definitions file is the source of truth for permission metadata. Subject overrides stay small: permission ID plus boolean value.

{
  "documents.approve": {
    "name": "Approve Documents",
    "description": "Can approve routed documents",
    "category": "Documents",
    "default": false
  }
}

Resolution

User override
   ↓ none
Group overrides
   ↓ none
Permission default
   ↓
Allow / Deny

Prefab Users can provide the same simple groups you created earlier. Permissions then adds group permission overrides rather than creating a duplicate group system.

Typical check

if ($permissions->can($user, 'documents.approve')) {
    // allow the action
}
Checkpoint: define one permission, assign it to a group, and verify a member receives the expected result.
