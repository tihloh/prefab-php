Input and validation

Build a small working form with plain HTML. Invalid input shows useful messages and valid input produces a normal success result.

1. Install Input

composer require tihloh/prefab-input

2. Process the form

Create public/input.php and start with the PHP logic:

<?php
require __DIR__ . '/../vendor/autoload.php';

use Tihloh\Prefab\Input\Input;

$errors = [];
$valid = null;

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    $result = Input::from($_POST)->process([
        'name' => 'trim|required|string|max:100',
        'email' => 'trim|lowercase|required|email',
        'age' => 'required|integer|min:18',
    ]);

    $errors = $result->errors();
    $valid = $result->fails() ? null : $result->validated();
}
?>

3. Add the form

No framework or full HTML document is needed for this lesson:

<h1>Registration</h1>

<form method="post">
    <p><input name="name" placeholder="Name"></p>
    <p><input name="email" placeholder="Email"></p>
    <p><input name="age" placeholder="Age"></p>
    <button>Register</button>
</form>

4. Show validation errors

Show errors where a student expects them instead of printing the PHP array:

<?php if ($errors): ?>
    <p><b>Please fix these errors:</b></p>
    <ul>
        <?php foreach ($errors as $field => $messages): ?>
            <li><?= htmlspecialchars($field) ?>: <?= htmlspecialchars($messages[0]) ?></li>
        <?php endforeach; ?>
    </ul>
<?php endif; ?>

5. Show success

<?php if ($valid): ?>
    <p><b>Registration successful!</b></p>
    <p>Welcome, <?= htmlspecialchars($valid['name']) ?>.</p>
<?php endif; ?>
Checkpoint: Enter an invalid email or age below 18 to see validation errors. Enter valid values to see the success message.

6. Understand the rules

'name'  => 'trim|required|string|max:100'
'email' => 'trim|lowercase|required|email'
'age'   => 'required|integer|min:18'

trim and lowercase transform values. The other rules decide whether the submitted values are acceptable.

7. Use validated data

The useful result is not the debug output. It is data that can now be safely handed to another module:

if ($valid) {
    $users->create($valid);
}

8. Developer tip: inspect values

print_r($result->errors());
print_r($result->validated());

These are useful while debugging, but they should not be the application's visible result.

9. Advanced: request and upload helpers

For forms that include files, Input::fromRequest() can collect normal request values and uploaded-file data together. File rules can validate type, MIME and size before Files stores the upload.

Works with other Prefab modules

Prefab Input is intentionally request-focused. It does not auto-save anything, but its validated values and UploadedFile objects are designed to pass cleanly into other modules.

ModuleIntegrationHowWhat happens
FilesDirect compatible handoffUploadedFile → FileManager::storeUploaded()Validate an upload with Input, then pass the validated UploadedFile directly to Files for permanent storage.
UsersDirect compatible handoffvalidated() → UserManager::create/update()Only validated/whitelisted form fields need to be passed to Users.
AuthDirect compatible handoffvalidated identifier/password/PINA login form can validate its fields first, then pass them to Auth.
Important: Input does not automatically call another module because validation should never silently cause a database write, login or file save.
