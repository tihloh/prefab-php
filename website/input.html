Input and validation

Build a small form that behaves like a real application: invalid fields show useful messages and valid input shows a success message. We will use short snippets and improve the page one step at a time.

1. Install Input

composer require tihloh/prefab-input

Prefab Input is standalone. It can validate arrays, form submissions and uploaded files without requiring Database, Users, Routes or Auth.

2. Process the form

Create public/input.php and start with the PHP logic:

<?php
require __DIR__ . '/../vendor/autoload.php';

use Tihloh\Prefab\Input\Input;

$errors = [];
$valid = null;

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    $result = Input::from($_POST)->process([
        'name' => 'trim|required|string|max:100',
        'email' => 'trim|lowercase|required|email',
        'age' => 'required|integer|min:18',
    ]);

    $errors = $result->errors();
    $valid = $result->fails() ? null : $result->validated();
}
?>

process() validates and transforms the fields declared in the rules. Keep this processing block above the page content.

3. Add a simple form

Add only the form markup you need:

<form method="post" class="card card-body">
    <input name="name" class="form-control mb-2" placeholder="Name">
    <input name="email" class="form-control mb-2" placeholder="Email">
    <input name="age" class="form-control mb-2" placeholder="Age">
    <button class="btn btn-primary">Submit</button>
</form>

The name attributes become the keys in $_POST. The Bootstrap classes are only presentation; Prefab handles the validation.

4. Show errors like a real form

Instead of dumping the errors array, show a clear message to the user:

<?php if ($errors): ?>
    <div class="alert alert-danger mt-3">
        Please check the form and try again.
    </div>
<?php endif; ?>

Later you can place individual field messages beside each input. For now the student gets an immediate, visible validation result without reading a PHP array dump.

5. Show success

When validation passes, give the user a normal application response:

<?php if ($valid): ?>
    <div class="alert alert-success mt-3">
        Welcome, <?= htmlspecialchars($valid['name']) ?>!
    </div>
<?php endif; ?>
Checkpoint: Submit an invalid email or age below 18 and see the error alert. Submit valid values and see the welcome message.

6. Understand the rules

'name'  => 'trim|required|string|max:100'
'email' => 'trim|lowercase|required|email'
'age'   => 'required|integer|min:18'

trim and lowercase transform values. required, email, integer, min and max decide whether the values are acceptable.

7. Use validated data

validated() returns only the fields declared in your rules. That makes it a clean handoff to another module:

if ($valid) {
    $users->create($valid);
}

This is the normal application flow: validate first, then pass accepted data to Users, Database or your own service.

8. Developer tip: inspect the result

While debugging, you can temporarily inspect the raw result:

print_r($result->errors());
print_r($result->validated());

Use this for development only. The tutorial's visible result should be the form feedback, not the debug output.

9. Advanced: request and upload helpers

For forms that include files, Input::fromRequest() can collect normal request values and uploaded-file data together. File rules can validate type, MIME and size before Files stores the upload.

Works with other Prefab modules

Prefab Input is intentionally request-focused. It does not auto-save anything, but its validated values and UploadedFile objects are designed to pass cleanly into other modules.

ModuleIntegrationHowWhat happens
FilesDirect compatible handoffUploadedFile → FileManager::storeUploaded()Validate an upload with Input, then pass the validated UploadedFile directly to Files for permanent storage.
UsersDirect compatible handoffvalidated() → UserManager::create/update()Only validated/whitelisted form fields need to be passed to Users. Raw request fields stay out of persistence.
AuthDirect compatible handoffvalidated identifier/password/PINA login form can validate/normalize its fields first, then pass them to attempt() or attemptPin().
Any moduleDirect compatible handoffInputResult::validated()Validated input is plain PHP data, so it can safely become service-method arguments throughout the application.
Important: Input does not automatically call another module because validation should never silently cause a database write, login or file save.
