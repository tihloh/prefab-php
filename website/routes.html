Routing

Routing connects an HTTP request such as GET /users/25 to the PHP code that should handle it. This tutorial starts with two routes, then gradually adds parameters, HTTP methods, middleware, route groups, named URLs and diagnostics.

1. Install Routes

composer require tihloh/prefab-routes

The Routes package provides RouteManager. Think of the manager as a registry of URL rules. Each rule contains an HTTP method, a path and a handler.

2. Create the first routes

Replace public/index.php with:

<?php
require __DIR__ . '/../vendor/autoload.php';

use Tihloh\Prefab\Routes\RouteManager;

$routes = new RouteManager();

$routes->get('/', fn () => '<h1>Prefab Routes</h1><p>Router is working.</p>');
$routes->get('/hello/{name}', fn (string $name) => "Hello {$name}");

$result = $routes->dispatch();
if (is_string($result)) echo $result;

$routes->get() registers a route that responds only to HTTP GET requests. The first argument is the URL pattern. The second argument is the handler that runs when the request matches.

The {name} part is a route parameter. For /hello/Alice, Routes extracts Alice and passes it to the handler as $name.

dispatch() reads the current HTTP method and requested URL, finds the matching route, then executes its handler. Register routes before calling dispatch(), because the router cannot match rules that have not been registered yet.

3. Run and test

php -S 127.0.0.1:8000 -t public

Open http://127.0.0.1:8000/, then http://127.0.0.1:8000/hello/Alice.

Checkpoint: The home URL should show the Routes message and /hello/Alice should display Hello Alice.

4. HTTP methods

A URL alone does not identify an HTTP action. Web applications commonly use GET to read data, POST to create or submit data, PUT/PATCH to update, and DELETE to remove. Routes lets the same path behave differently depending on the method.

$routes->get('/method/get', fn () => 'GET');
$routes->post('/method/post', fn () => 'POST');
$routes->put('/method/put', fn () => 'PUT');
$routes->patch('/method/patch', fn () => 'PATCH');
$routes->delete('/method/delete', fn () => 'DELETE');
$routes->any('/method/any', fn () => 'ANY');
$routes->matchMethods(['GET','POST'], '/method/both', fn () => 'GET or POST');

A normal browser address bar sends GET requests. Use an HTML form, curl or Postman to test the other methods.

5. Required and optional parameters

$routes->get('/users/{id}', fn ($id) => "User {$id}");
$routes->get('/reports/{year?}', fn ($year) => "Report {$year}")
    ->defaults(['year' => date('Y')]);

{id} is required, so /users/25 matches but /users does not. The question mark in {year?} makes the parameter optional. defaults() supplies a value when the optional part is absent.

6. Constrain parameter values

$routes->get('/numbers/{id}', fn ($id) => "Number {$id}")
    ->where('id', '\d+');

The regular expression \d+ means one or more digits. This prevents a route intended for numeric IDs from also accepting arbitrary text. /numbers/25 matches; /numbers/test does not.

7. Name routes and generate URLs

$routes->get('/profiles/{id}', fn ($id) => "Profile {$id}")
    ->name('profiles.show');

echo $routes->url('profiles.show', ['id' => 25]);
echo $routes->url('profiles.show', ['id' => 25, 'tab' => 'activity']);

A route name is a stable application-level identifier. Instead of hard-coding /profiles/25 throughout the application, code can ask Routes to generate the URL by name. If the path changes later, callers do not need to change.

Parameters used by the route fill placeholders. Extra values become query-string parameters, so tab=activity is appended to the generated URL.

8. Group related routes

$routes->group('/admin', function (RouteManager $routes) {
    $routes->get('/users', fn () => 'Admin users');
    $routes->get('/logs', fn () => 'Admin logs');
});

The group prefix is added to every route inside the callback. These become /admin/users and /admin/logs. Groups reduce repetition and make related routes easier to organize.

Advanced group options

$routes->group([
    'prefix' => '/api',
    'name' => 'api.',
    'meta' => ['area' => 'api'],
], function (RouteManager $routes) {
    $routes->get('/status', fn () => 'OK')->name('status');
});

This form applies a path prefix, a route-name prefix and shared metadata. The route name becomes api.status.

9. Run code before a route with middleware

Middleware sits between the incoming request and the final handler. It is useful for authentication, permission checks, rate limits, request logging and other rules that should run before selected routes.

$routes->middleware('demo-auth', function (callable $next, $match) {
    if (($_GET['key'] ?? '') !== 'secret') {
        http_response_code(401);
        return 'Unauthorized. Add ?key=secret';
    }
    return $next();
});

$routes->get('/protected', fn () => 'Protected page')
    ->middleware('demo-auth');

If the key is missing, middleware returns early and the route handler never runs. Calling $next() passes control to the next middleware or route handler. Test /protected, then /protected?key=secret.

10. Redirects and fallback routes

$routes->redirect('/old-page', '/');
$routes->redirect('/old-permanent', '/', 301);

$routes->fallback(function () {
    http_response_code(404);
    return 'Custom 404';
});

A redirect tells the browser to request another URL. A 301 redirect indicates a permanent move. A fallback runs only when no normal route matches and is commonly used for a custom 404 response.

11. Metadata, tags and integration hints

$routes->get('/documents/{id}', fn ($id) => "Document {$id}")
    ->name('documents.show')
    ->tag('documents', 'demo')
    ->meta(['title' => 'Document Details'])
    ->auth()
    ->permission('documents.view')
    ->log('documents.view');

Tags are useful for finding related routes. Metadata stores descriptive information alongside a route. The auth(), permission() and log() helpers describe integration requirements; they do not magically authenticate or authorize the request by themselves. Middleware or integration code reads those requirements and performs the actual enforcement.

12. Advanced: controller handlers

Closures are useful while learning, but larger applications usually move logic into controller classes.

$routes = new RouteManager([
    'controller_namespace' => 'App\\Controllers',
]);

$routes->get('/users/{id}', 'UserController@show');
// or
$routes->get('/users/{id}', [App\Controllers\UserController::class, 'show']);

This keeps route definitions focused on URLs while controllers contain application behavior.

13. Advanced: resource routes

use App\Controllers\UserController;
$routes->resource('/users', UserController::class);

A resource route creates the conventional collection of CRUD routes for a controller. It is convenient once the student already understands the individual GET, POST, update and delete routes that it represents.

14. Advanced: route arrays and separate files

$routes = new RouteManager([
    'routes' => [
        ['GET', '/', fn () => 'Home', 'home'],
        [
            'method' => 'GET',
            'path' => '/items/{id}',
            'handler' => fn ($id) => "Item {$id}",
            'name' => 'items.show',
            'constraints' => ['id' => '\d+'],
            'tags' => ['items'],
        ],
    ],
]);

Array definitions are useful when routes come from configuration rather than direct method calls.

Create routes/web.php:

<?php
return [
    ['GET', '/from-file', fn () => 'Loaded from routes/web.php', 'from-file'],
];

Load the file before dispatch:

$routes->load(__DIR__ . '/../routes/web.php');

Separate route files keep public/index.php small as the application grows.

15. Advanced: inspect routing without executing it

$match = $routes->match('GET', '/users/25');
if ($match) {
    print_r($match->parameters());
}

match() asks “which route would handle this request?” without running the handler. This is useful for tests and diagnostics.

print_r($routes->all());
print_r($routes->find('profiles.show'));
print_r($routes->byTag('documents'));
print_r($routes->toArray());
print_r($routes->table());
print_r($routes->explain());

explain() is especially useful when routes conflict or integrations are resolved unexpectedly.

$routes->get('/duplicate', fn () => 'A');
$routes->get('/duplicate', fn () => 'B');
print_r($routes->explain());

The diagnostic output should identify the duplicate GET /duplicate definition.

16. Static files are not routes

CSS, JavaScript, images and fonts should normally be stored under public and served directly by the web server. Routes is for application requests that require PHP logic.

Works with other Prefab modules

Prefab Routes stays independent, but it can carry neutral metadata that other Prefab modules or middleware can interpret. This lets routing cooperate with Auth, Permissions and Logs without making those packages hard dependencies.

ModuleIntegrationHowWhat happens
AuthCompatible hookroute.auth()Marks a route as requiring authentication in route metadata. An auth middleware or integration layer reads the metadata and enforces the requirement.
PermissionsCompatible hookroute.permission("documents.view")Stores the required permission on the route. Permission middleware can call PermissionManager::can() before the controller runs.
LogsCompatible hookroute.log("documents.view")Stores the intended audit action on the route. A logging middleware/integration can record it after or around the handler.
Auth + Permissions + LogsComposablemiddleware pipelineA protected route can authenticate the current user, resolve a permission, run the controller and then record activity as one request pipeline.
Important: Routes does not silently enforce Auth or Permissions by itself. The route helpers intentionally attach metadata so an application can decide how enforcement should work.
