Runtime & Diagnostics

Core connects Prefab modules through capabilities and provides developer diagnostics without forcing feature packages to depend directly on each other.

1. Normal trace

$users->create($data);

prefab_trace();

The normal trace is intended to stay readable: module, operation, meaningful steps and result.

2. Detailed trace

$users->create($data);

prefab_trace_detailed();

Detailed mode may include timings and lower-level diagnostics such as SQL where available, while sensitive values should remain redacted.

3. Configuration explanation

$database->explain();
$logs->explain();

Use explain() when you need to understand how a module resolved configuration, storage or another Prefab capability.

4. Runtime composition

Modules publish and resolve capabilities through Core instead of importing optional feature packages directly. This keeps packages modular while still allowing automatic integration when compatible modules are installed.

Users ───────┐
Auth ────────┼─ Core capabilities ─ Logs
Permissions ─┘

5. Core is infrastructure, not business logic

Core may provide connection, session, cache, tracing and runtime mechanics. It should not decide application-specific rules such as who may log in, who can approve a document or when a notification should be sent.
