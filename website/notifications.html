Notifications

Notifications are persistent messages shown inside the application, such as “Your document was approved.” This tutorial stores notifications per recipient, shows unread counts, and lets the user mark items read, unread or deleted.

1. Install Notifications

composer require tihloh/prefab-notifications

NotificationManager provides the application-facing API. A notification store decides where messages are kept. This tutorial uses PdoNotificationStore so notifications survive browser refreshes.

2. Create the notification table

CREATE TABLE notifications (
    id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    recipient_id VARCHAR(191) NOT NULL,
    title VARCHAR(191) NOT NULL,
    message TEXT NOT NULL,
    metadata JSON NOT NULL,
    action_url VARCHAR(500) NULL,
    created_at DATETIME NOT NULL,
    read_at DATETIME NULL,
    INDEX idx_notifications_recipient (recipient_id),
    INDEX idx_notifications_read (read_at)
);

Unlike some other Prefab modules, the PDO notification store does not automatically invent a schema because projects often already have a notification table. For this tutorial, create the expected table explicitly.

recipient_id identifies who should see the notification. read_at is NULL while unread and contains a timestamp after the notification is read. metadata stores additional structured data, while action_url can point to the related page.

3. Connect the notification store

Create public/notifications.php:

<?php
require __DIR__ . '/../vendor/autoload.php';

use Tihloh\Prefab\Notifications\NotificationManager;
use Tihloh\Prefab\Notifications\Stores\PdoNotificationStore;

$pdo = new PDO(
    'mysql:host=127.0.0.1;dbname=prefab_tutorial;charset=utf8mb4',
    'root', '', [PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION]
);

$notifications = new NotificationManager(
    new PdoNotificationStore($pdo)
);

$recipient = (int) ($_GET['user'] ?? 1);

The tutorial uses recipient #1 by default. Passing ?user=2 in the URL lets you see how separate recipients receive separate notification lists.

4. Send one notification

Add a temporary send call:

$notifications->send(
    $recipient,
    'Document Approved',
    'OBR-2026-001 has been approved.',
    ['document_id' => 1001],
    '/documents/1001',
);

The arguments are recipient, title, message, metadata and optional action URL. The manager creates the notification and the PDO store persists it.

Checkpoint: The notifications table should contain one unread record for recipient #1.

5. Send notifications from a form

Remove the temporary send call and add:

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    $action = $_POST['action'] ?? 'send';

    if ($action === 'send') {
        $notifications->send(
            $recipient,
            $_POST['title'] ?? 'Document Approved',
            $_POST['message'] ?? 'OBR-2026-001 has been approved.',
            ['document_id' => 1001],
            '/documents/1001',
        );
    }
}

$recent = $notifications->recent($recipient);
$count = $notifications->unreadCount($recipient);

recent() retrieves the recipient's notifications. unreadCount() is useful for badges such as the number shown beside a bell icon.

Add the form:

<h1>Prefab Notifications Test</h1>
<p>Recipient #<?= $recipient ?> — unread: <?= $count ?></p>

<form method="post">
    <p><input name="title" value="Document Approved"></p>
    <p><textarea name="message">OBR-2026-001 has been approved.</textarea></p>
    <button name="action" value="send">Send notification</button>
</form>
Checkpoint: Send several notifications and confirm the unread counter increases.

6. Display the notification list

<h2>Notifications</h2>
<?php foreach ($recent as $n): ?>
    <form method="post" style="border:1px solid #ccc;padding:10px;margin:10px 0">
        <input type="hidden" name="id" value="<?= htmlspecialchars((string) $n->id) ?>">
        <b><?= htmlspecialchars($n->title) ?></b>
        <p><?= htmlspecialchars($n->message) ?></p>
        <p>State: <?= $n->readAt ? 'READ' : 'UNREAD' ?></p>
        <button name="action" value="read">Mark read</button>
        <button name="action" value="unread">Mark unread</button>
        <button name="action" value="delete">Delete</button>
    </form>
<?php endforeach; ?>

Each form carries the notification ID in a hidden input. That ID tells the next POST request which notification should be changed.

7. Handle read, unread and delete actions

Add these cases inside the existing POST handler:

if ($action === 'read') {
    $notifications->markRead($_POST['id']);
}

if ($action === 'unread') {
    $notifications->markUnread($_POST['id']);
}

if ($action === 'delete') {
    $notifications->delete($_POST['id']);
}

markRead() sets a read timestamp. markUnread() clears it. The unread counter is therefore derived from stored notification state rather than maintained as a separate number that could become inconsistent.

Checkpoint: Mark notifications read and unread and confirm the counter changes. Delete one and confirm it disappears after refresh.

8. Core API

$notifications->send($userId, $title, $message, $metadata, $actionUrl);
$notifications->recent($userId);
$notifications->unread($userId);
$notifications->unreadCount($userId);
$notifications->markRead($notificationId);
$notifications->markUnread($notificationId);
$notifications->delete($notificationId);

unread() returns the actual unread records, while unreadCount() returns only the number. Use the cheaper result that the current screen needs.

9. In-memory mode

$notifications = new NotificationManager();

With no persistent store, the manager uses an in-memory store. This is useful for tests and same-process experiments. It is not suitable for normal browser notifications because PHP request memory disappears when the request ends.

10. Advanced: existing notification tables

If a project already has a table with different column names, configure the PDO store's column mapping rather than renaming the application's schema. This follows Prefab's general design: adapt the module to the host application instead of forcing the host application to look like Prefab.
