Notifications

Build a small in-application notification page. You will send notices, display them, count unread items, and change their read state.

1. Install

composer require tihloh/prefab-notifications

2. Create storage

CREATE TABLE notifications (
    id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    recipient_id VARCHAR(191) NOT NULL,
    title VARCHAR(191) NOT NULL,
    message TEXT NOT NULL,
    metadata JSON NOT NULL,
    action_url VARCHAR(500) NULL,
    created_at DATETIME NOT NULL,
    read_at DATETIME NULL
);

3. Connect Notifications

<?php
require __DIR__ . '/../vendor/autoload.php';

use Tihloh\Prefab\Notifications\NotificationManager;
use Tihloh\Prefab\Notifications\Stores\PdoNotificationStore;

$notifications = new NotificationManager(
    new PdoNotificationStore($pdo)
);

$userId = 1;

The recipient ID can be the ID of the signed-in user. Notifications itself does not need to own the user account.

4. Send a notification

$notification = $notifications->send(
    $userId,
    'Document Approved',
    'OBR-2026-001 has been approved.',
    ['document_id' => 1001],
    '/documents/1001',
);
Checkpoint: One unread notification should now exist for user #1.

5. Add a simple form

<form method="post">
    <input name="title" placeholder="Title" required>
    <input name="message" placeholder="Message" required>
    <button>Send notification</button>
</form>
if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    $notifications->send(
        $userId,
        $_POST['title'],
        $_POST['message'],
    );
}

$recent = $notifications->recent($userId);
$count = $notifications->unreadCount($userId);

6. Show the result

<h1>Notifications</h1>
<p>Unread: <strong><?= $count ?></strong></p>

<table border="1" cellpadding="8">
    <tr>
        <th>Title</th>
        <th>Message</th>
        <th>State</th>
        <th>Action</th>
    </tr>
    <?php foreach ($recent as $n): ?>
    <tr>
        <td><?= htmlspecialchars($n->title) ?></td>
        <td><?= htmlspecialchars($n->message) ?></td>
        <td><?= $n->readAt ? 'Read' : 'Unread' ?></td>
        <td>
            <form method="post">
                <input type="hidden" name="id" value="<?= htmlspecialchars((string) $n->id) ?>">
                <button name="action" value="read">Read</button>
                <button name="action" value="unread">Unread</button>
                <button name="action" value="delete">Delete</button>
            </form>
        </td>
    </tr>
    <?php endforeach; ?>
</table>

The page now has an actual notification interface instead of displaying internal PHP structures.

7. Handle the buttons

$action = $_POST['action'] ?? null;
$id = $_POST['id'] ?? null;

if ($action === 'read') {
    $notifications->markRead($id);
}
if ($action === 'unread') {
    $notifications->markUnread($id);
}
if ($action === 'delete') {
    $notifications->delete($id);
}
Checkpoint: Mark an item read and confirm the unread number decreases. Mark it unread and the number increases again.

8. Developer tip: inspect the last Prefab operation

When operation tracing is available for the module, place one line after the operation you want to inspect:

$notifications->send($userId, $title, $message);

prefab_trace();

Use prefab_trace(true) when you need the detailed internal steps. Tracing is for development; your application interface should continue showing normal user-facing results.

9. In-memory mode

$notifications = new NotificationManager();

This is useful for tests and same-process experiments. Browser applications normally need persistent storage because PHP request memory ends after each request.

10. What you built

You now have a small internal notification center with persistent notices, an unread counter and read/unread/delete actions.

Next: Continue to Messaging to send information outside the application through email or another delivery channel.
