Users

Prefab Users keeps user management short. Start with a PDO connection and UserManager. Prefab creates its default user table automatically when needed. Mapping existing schemas and custom providers are optional and come later.

1. Install

composer require tihloh/prefab-users

2. Connect and use Users

Create public/users.php. If the database exists but the default users table does not, Prefab creates it automatically.

<?php
require __DIR__ . '/../vendor/autoload.php';

use Tihloh\Prefab\Users\Services\UserManager;

$pdo = new PDO(
    'mysql:host=127.0.0.1;dbname=prefab_tutorial;charset=utf8mb4',
    'root',
    '',
    [PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION]
);

$users = new UserManager([
    'database' => $pdo,
]);

$user = $users->find(1);
?>

<h1>User</h1>
<p><?= htmlspecialchars($user?->name ?? 'Not found') ?></p>

UserManager is the normal application API. The package chooses the built-in database provider internally, so beginner code does not need to create a provider manually.

Start the development server:

php -S 127.0.0.1:8000 -t public

Open http://127.0.0.1:8000/users.php. A new database will show Not found because there is no user yet. That is expected.

Checkpoint: The page loads without a missing-table error.

3. Create the first user

Add this before $user = $users->find(1);:

if (!$users->find(1)) {
    $users->create([
        'name' => 'Alice',
        'email' => 'alice@example.com',
        'active' => true,
    ]);
}

Refresh the page.

Checkpoint: The page should display Alice.

4. List users

Replace the single lookup with:

$list = $users->all();

Then display the result:

<h1>Users</h1>
<?php foreach ($list as $user): ?>
    <p>
        #<?= $user->id ?>
        <?= htmlspecialchars($user->name ?? '') ?>
        — <?= htmlspecialchars($user->email ?? '') ?>
    </p>
<?php endforeach; ?>

htmlspecialchars() displays user-provided text safely instead of allowing it to become HTML.

5. Create users from a form

Add this before loading the list:

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    $users->create([
        'name' => trim($_POST['name'] ?? ''),
        'email' => trim($_POST['email'] ?? ''),
        'active' => true,
    ]);
}

Add the form:

<form method="post">
    <input name="name" placeholder="Name" required>
    <input name="email" type="email" placeholder="Email" required>
    <button>Create</button>
</form>

The HTML name becomes the PHP $_POST key. For example, name="email" becomes $_POST['email'].

Checkpoint: Create Bob. He should appear in the list.

6. Find and update

Find by ID or email:

$user = $users->find(1);
$byEmail = $users->findByEmail('alice@example.com');

Update only the fields that need to change:

$users->update(1, [
    'name' => 'Alice Smith',
]);

Disable a user without deleting the record:

$users->update(1, ['active' => false]);

7. Optional: map an existing table

If the application already has a user table, map its existing names. Prefab uses the table as-is.

use Tihloh\Prefab\Users\Mapping\UserMap;

$map = new UserMap(
    table: 'employees',
    id: 'employee_id',
    name: 'full_name',
    email: 'email_address',
    active: 'is_active',
);

$users = new UserManager([
    'database' => $pdo,
    'map' => $map,
]);

This keeps the simple UserManager API while adapting Prefab to an existing schema.

8. Optional: custom fields

Map project-specific columns through attributes:

$map = new UserMap(
    table: 'employees',
    id: 'employee_id',
    name: 'full_name',
    email: 'email_address',
    active: 'is_active',
    attributes: [
        'office' => 'office_name',
        'position' => 'position_title',
    ],
);

Read them with:

echo $user->get('office');
echo $user->get('position');

9. Optional: restrict writes or allow delete

Existing directories are often read-only. Control that in the map:

$map = new UserMap(
    table: 'employees',
    id: 'employee_id',
    name: 'full_name',
    email: 'email_address',
    active: 'is_active',
    allowCreate: false,
    allowUpdate: false,
    allowDelete: false,
);

If deletion is intentionally allowed, set allowDelete: true and call:

$users->delete($userId);

10. Optional: custom provider and diagnostics

Most applications do not need to construct PdoUserProvider directly. It remains available for lower-level or custom integrations. The preferred application setup is still:

$users = new UserManager([
    'database' => $pdo,
    'map' => $map,
]);

When several Prefab modules are installed, inspect automatic resolution with:

print_r($users->explain());

Password credentials are not stored in the Users profile table. The Authentication module owns credentials while Users owns identity and profile data.

Next: Continue to Authentication to add login and sessions.

Works with other Prefab modules

Prefab Users provides identity/profile data and publishes its user provider so other modules can reuse the same users instead of creating another account system.

ModuleIntegrationHowWhat happens
DatabaseAutomaticdatabase capabilityUsers can discover the shared database and create its default PDO user provider automatically.
AuthAutomaticuser_provider capabilityAuth detects Prefab Users and uses the same user identity/profile data.
LogsAutomaticlogger capabilityCreate, update and delete activity can be recorded automatically when Prefab Logs is available.
Auth → Users logsAutomatic actor contextactor_provider capabilityUsers can use the authenticated user ID as the actor for audit records.
PermissionsCompatibleuser ID / groupsThe same user ID can be used directly by PermissionManager.
Keep it simple: Users owns profile/identity data. Auth owns credentials. Permissions owns authorization. Logs owns history.
