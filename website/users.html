Users

Build a small user-management screen one piece at a time. Start with UserManager, show real users, then add a form. Mapping and diagnostics stay optional.

1. Install

composer require tihloh/prefab-users

2. Connect Users

Create public/users.php. If the database exists but the default users table does not, Prefab creates it automatically.

<?php
require __DIR__ . '/../vendor/autoload.php';

use Tihloh\Prefab\Users\Services\UserManager;

$pdo = new PDO(
    'mysql:host=127.0.0.1;dbname=prefab_tutorial;charset=utf8mb4',
    'root', '',
    [PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION]
);

$users = new UserManager(['database' => $pdo]);
$list = $users->all();
?>

UserManager is the normal application API. Beginner code does not need to construct a provider manually.

3. Show a useful Users screen

Instead of printing the array, display the users as a small Bootstrap list:

<h1>Users</h1>

<?php foreach ($list as $user): ?>
    <div class="card card-body mb-2">
        <strong><?= htmlspecialchars($user->name ?? '') ?></strong>
        <small class="text-muted"><?= htmlspecialchars($user->email ?? '') ?></small>
    </div>
<?php endforeach; ?>

Start the server with php -S 127.0.0.1:8000 -t public and open users.php.

Checkpoint: You now have the beginning of a real Users page, even if the list is empty.

4. Add a user form

Add a small form above the list:

<form method="post" class="card card-body mb-3">
    <input name="name" class="form-control mb-2" placeholder="Name" required>
    <input name="email" type="email" class="form-control mb-2" placeholder="Email" required>
    <button class="btn btn-primary">Add user</button>
</form>

Then add the POST handling before $list = $users->all();:

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    $users->create([
        'name' => trim($_POST['name'] ?? ''),
        'email' => trim($_POST['email'] ?? ''),
        'active' => true,
    ]);
}
Checkpoint: Add Alice or Bob from the browser. The new user should appear in the list.

5. Show status

Add a status badge inside each user card:

<span class="badge text-bg-<?= $user->active ? 'success' : 'secondary' ?>">
    <?= $user->active ? 'Active' : 'Inactive' ?>
</span>

Now the screen communicates useful application state instead of exposing raw PHP data.

6. Find and update

Normal everyday operations stay short:

$user = $users->find(1);
$byEmail = $users->findByEmail('alice@example.com');

$users->update(1, ['name' => 'Alice Smith']);
$users->update(1, ['active' => false]);

7. Optional: map an existing table

If the application already has a user table, map its existing names:

use Tihloh\Prefab\Users\Mapping\UserMap;

$map = new UserMap(
    table: 'employees',
    id: 'employee_id',
    name: 'full_name',
    email: 'email_address',
    active: 'is_active',
);

$users = new UserManager([
    'database' => $pdo,
    'map' => $map,
]);

8. Optional: custom fields

$map = new UserMap(
    table: 'employees',
    attributes: [
        'office' => 'office_name',
        'position' => 'position_title',
    ],
);

Then use them normally in your UI:

<small><?= htmlspecialchars($user->get('office') ?? '') ?></small>

9. Optional: restrict writes or allow delete

$map = new UserMap(
    table: 'employees',
    allowCreate: false,
    allowUpdate: false,
    allowDelete: false,
);

If deletion is intentionally allowed, set allowDelete: true and call $users->delete($userId).

10. Developer tip: diagnostics

If automatic integration is not behaving as expected, temporarily inspect it:

print_r($users->explain());

This is a debugging tool, not the application's user interface. Password credentials are not stored in the Users profile table; Authentication owns credentials while Users owns identity and profile data.

Next: Continue to Authentication and turn this into a login-enabled application.

Works with other Prefab modules

Prefab Users provides identity/profile data and publishes its user provider so other modules can reuse the same users instead of creating another account system.

ModuleIntegrationHowWhat happens
DatabaseAutomaticdatabase capabilityUsers can discover the shared database and create its default PDO user provider automatically.
AuthAutomaticuser_provider capabilityAuth detects Prefab Users and uses the same user identity/profile data.
LogsAutomaticlogger capabilityCreate, update and delete activity can be recorded automatically when Prefab Logs is available.
Auth → Users logsAutomatic actor contextactor_provider capabilityUsers can use the authenticated user ID as the actor for audit records.
PermissionsCompatibleuser ID / groupsThe same user ID can be used directly by PermissionManager.
Keep it simple: Users owns profile/identity data. Auth owns credentials. Permissions owns authorization. Logs owns history.
