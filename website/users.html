Users

Build a simple user-management page with plain HTML, then use Prefab tracing and explanation output as optional developer diagnostics.

1. Install

composer require tihloh/prefab-users

2. Connect Users

<?php
require __DIR__ . '/../vendor/autoload.php';

use Tihloh\Prefab\Users\Services\UserManager;

$pdo = new PDO(
    'mysql:host=127.0.0.1;dbname=prefab_tutorial;charset=utf8mb4',
    'root',
    '',
    [PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION]
);

$users = new UserManager(['database' => $pdo]);

3. Add a user

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    $users->create([
        'name' => trim($_POST['name'] ?? ''),
        'email' => trim($_POST['email'] ?? ''),
        'active' => true,
    ]);
}

$list = $users->all();
<form method="post">
    <input name="name" placeholder="Name" required>
    <input name="email" type="email" placeholder="Email" required>
    <button>Add user</button>
</form>

4. Display users

<h1>Users</h1>
<table border="1" cellpadding="8">
    <tr><th>ID</th><th>Name</th><th>Email</th><th>Status</th></tr>
    <?php foreach ($list as $user): ?>
    <tr>
        <td><?= $user->id ?></td>
        <td><?= htmlspecialchars($user->name ?? '') ?></td>
        <td><?= htmlspecialchars($user->email ?? '') ?></td>
        <td><?= $user->active ? 'Active' : 'Inactive' ?></td>
    </tr>
    <?php endforeach; ?>
</table>
Checkpoint: Submit the form and confirm the new user appears in the table.

5. Find, update and delete

$user = $users->find(1);
$byEmail = $users->findByEmail('alice@example.com');

$users->update(1, ['name' => 'Alice Smith']);
// $users->delete(1); // only when deletion is enabled by the map

6. Map an existing table

use Tihloh\Prefab\Users\Mapping\UserMap;

$map = new UserMap(
    table: 'employees',
    id: 'employee_id',
    name: 'full_name',
    email: 'email_address',
    active: 'is_active',
);

$users = new UserManager([
    'database' => $pdo,
    'map' => $map,
]);

7. Developer diagnostic: trace this request

prefab_trace() prints the Prefab operations that completed during the current PHP request. It is not a log table and it does not store history between requests.

Place it after the page has finished doing the Prefab work you want to inspect:

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    $users->create($data);
}

$list = $users->all();
$recent = $logs->recent(20);

prefab_trace();

If the form created a user and the page then loaded users and activity, the trace can contain several operations instead of showing only the last database query:

Prefab Trace

1. users::user.created [OK]
   actor_id: null
   subject_id: 9
   result: Tihloh\Prefab\Users\User\PrefabUser
   duration: 0.120 ms

2. database::select [OK]
   bindings: 0
   result: array(3)
   duration: 0.850 ms

3. database::select [OK]
   bindings: 0
   result: array(2)
   duration: 1.799 ms

The exact operations depend on which modules are installed and which calls are instrumented. A database operation may appear because Users or Logs used the shared database internally.

Detailed trace

prefab_trace(true);

Detailed mode includes timed internal trace steps such as capability resolution and nested operations. Use it when the normal summary is not enough.

Important: Call prefab_trace() only for development diagnostics. It prints into the response, so remove or disable it on normal production pages.

8. Explain how Users was configured

explain() answers a different question from tracing. Trace shows what operations ran during this request. Explain shows where this module got its dependencies and configuration.

$users->explain();

It now prints a human-readable explanation instead of requiring print_r() on a raw array. Example:

Prefab Users Explain

Database:
  Source: module-local
  Meaning: Configured directly on this module instance.
  Driver: mysql

User Provider:
  Source: database-provider
  Meaning: Automatically created from the resolved database.
  Provider: Tihloh\Prefab\Users\Repositories\PdoUserProvider

Table:
  Source: internal-default
  Meaning: Using the package default because nothing more explicit was configured.
  Table: users

The method still returns the structured resolution array for backward compatibility. Code that specifically needs only structured data can use PrefabRuntime::explainData('users').

9. Trace vs explain

DiagnosticQuestion it answersTypical use
prefab_trace()What Prefab operations happened in this request?Follow create/read/log/database activity and timings.
prefab_trace(true)What internal trace steps happened inside those operations?Deeper debugging of resolution and nested calls.
$users->explain()How did Users resolve its provider, database, table and integrations?Debug configuration and auto-wiring.

Users owns identity/profile data. Auth owns credentials, Permissions owns authorization, and Logs owns persistent activity history.
