Users

Build a simple user-management page one piece at a time. Use plain HTML so the lesson stays focused on Prefab instead of a CSS framework.

1. Install

composer require tihloh/prefab-users

2. Connect Users

Create public/users.php. If the database exists but the default users table does not, Prefab creates it automatically.

<?php
require __DIR__ . '/../vendor/autoload.php';

use Tihloh\Prefab\Users\Services\UserManager;

$pdo = new PDO(
    'mysql:host=127.0.0.1;dbname=prefab_tutorial;charset=utf8mb4',
    'root', '',
    [PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION]
);

$users = new UserManager(['database' => $pdo]);
$list = $users->all();
?>

3. Display the users

A users list naturally belongs in a table. Add this below the PHP code:

<h1>Users</h1>

<table border="1" cellpadding="8">
    <tr>
        <th>ID</th><th>Name</th><th>Email</th><th>Status</th>
    </tr>
    <?php foreach ($list as $user): ?>
    <tr>
        <td><?= $user->id ?></td>
        <td><?= htmlspecialchars($user->name ?? '') ?></td>
        <td><?= htmlspecialchars($user->email ?? '') ?></td>
        <td><?= $user->active ? 'Active' : 'Inactive' ?></td>
    </tr>
    <?php endforeach; ?>
</table>

Start the server with php -S 127.0.0.1:8000 -t public and open users.php.

Checkpoint: You should see a real users table with ID, name, email and status columns.

4. Add a user

Add a small form above the table:

<form method="post">
    <input name="name" placeholder="Name" required>
    <input name="email" type="email" placeholder="Email" required>
    <button>Add user</button>
</form>

Then handle the form before loading $list:

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    $users->create([
        'name' => trim($_POST['name'] ?? ''),
        'email' => trim($_POST['email'] ?? ''),
        'active' => true,
    ]);
}

$list = $users->all();
Checkpoint: Add Alice or Bob. The new row should immediately appear in the table.

5. Find and update

Normal everyday operations stay short:

$user = $users->find(1);
$byEmail = $users->findByEmail('alice@example.com');

$users->update(1, ['name' => 'Alice Smith']);
$users->update(1, ['active' => false]);

Refresh the page after an update and the table shows the changed values.

6. Optional: map an existing table

use Tihloh\Prefab\Users\Mapping\UserMap;

$map = new UserMap(
    table: 'employees',
    id: 'employee_id',
    name: 'full_name',
    email: 'email_address',
    active: 'is_active',
);

$users = new UserManager([
    'database' => $pdo,
    'map' => $map,
]);

7. Optional: custom fields

$map = new UserMap(
    table: 'employees',
    attributes: ['office' => 'office_name'],
);

Add the mapped value as another table column when the application needs it:

<td><?= htmlspecialchars($user->get('office') ?? '') ?></td>

8. Optional: restrict writes or allow delete

$map = new UserMap(
    table: 'employees',
    allowCreate: false,
    allowUpdate: false,
    allowDelete: false,
);

If deletion is intentionally allowed, set allowDelete: true and call $users->delete($userId).

9. Developer tip: diagnostics

print_r($users->explain());

Use this only while debugging automatic integration. It is not the user interface.

Password credentials are not stored in the Users profile table. Authentication owns credentials while Users owns identity and profile data.

Works with other Prefab modules

Prefab Users provides identity/profile data and publishes its user provider so other modules can reuse the same users instead of creating another account system.

ModuleIntegrationHowWhat happens
DatabaseAutomaticdatabase capabilityUsers can discover the shared database and create its default PDO user provider automatically.
AuthAutomaticuser_provider capabilityAuth detects Prefab Users and uses the same user identity/profile data.
LogsAutomaticlogger capabilityCreate, update and delete activity can be recorded automatically when Prefab Logs is available.
PermissionsCompatibleuser ID / groupsThe same user ID can be used directly by PermissionManager.
Keep it simple: Users owns profile/identity data. Auth owns credentials. Permissions owns authorization. Logs owns history.
