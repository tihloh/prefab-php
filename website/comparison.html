Introduction

With Prefab vs without Prefab

A normal login already crosses at least three concerns: Users, Authentication and Logging.

Without Prefab

$stmt = $pdo->prepare('SELECT * FROM users WHERE email = ? LIMIT 1');
$stmt->execute([$email]);
$user = $stmt->fetch(PDO::FETCH_ASSOC);

if (!$user || !password_verify($password, $user['password'])) {
    $log = $pdo->prepare('INSERT INTO logs (event, message, created_at) VALUES (?, ?, NOW())');
    $log->execute(['auth.login_failed', $email]);
    throw new RuntimeException('Invalid credentials');
}

session_regenerate_id(true);
$_SESSION['user_id'] = $user['id'];

$log = $pdo->prepare('INSERT INTO logs (event, user_id, created_at) VALUES (?, ?, NOW())');
$log->execute(['auth.login', $user['id']]);

Your application manually coordinates user lookup, password verification, session state and audit logging.

With Prefab

use Tihloh\Prefab\Auth\Services\AuthManager;

$auth = new AuthManager();
$result = $auth->attempt($email, $password);

if (!$result->success) {
    // Your application decides the response.
}

When Prefab Users and Prefab Logs are available, Auth can use their compatible capabilities automatically.

Users ── user_provider ──┐
                         ├──→ Auth
Logs  ── logger ─────────┘
Install it. Use it. Compatible modules remove repetitive integration code while your application keeps control of its architecture.
